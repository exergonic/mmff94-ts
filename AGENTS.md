# AGENTS.md — mmff94-ts

**MMFF94 in pure TypeScript.** This file is the constitution: the durable
rules an agent (or human) needs before touching code. Volatile context
lives in `NOTES.md`; numbers live in generated reports; nothing here is a
status snapshot.

---

## The reader

This code is written for **chemists who code**, not software engineers.

- **Names use chemistry vocabulary.** If a concept has a chemistry name,
  that is the name (`buffered_14_7_vdw`, `partial_charges_from_bci`).
  Generic things get plain names (`i`, `dot`, `sum`). A forced chemistry
  name on a generic thing is worse than a plain one.
- **Comments explain why, not what.** Decision points where the *chemistry*
  drives a branch get comments; restatements of TypeScript are noise.
- **Simple beats clever.** If a block needs paragraphs of justification,
  simplify it. The longer-but-obvious version wins.
- **No architecture astronautics.** An abstraction needs two concrete users
  before it exists. Plain functions; no registries, no plugin systems.
- **The optimizer is the exception.** Inside `src/optimize/fast-system.ts`
  and the line search, performance is the domain: flat typed arrays,
  scalar math, dense comments about cache/ULP behavior are correct there.
  The readable term functions remain the ground truth; the fast path must
  match them within the documented tolerance, enforced by
  `tests/fast-system.test.ts`.
- **Never hand-build molecular structures.** Generate from SMILES via a
  toolkit, take them from the validation suite, or ask. Hand-typed
  coordinates carry silent errors.

## Truth discipline

1. **Generated numbers are never restated by hand.** The validation census
   lives in `docs/validation/report.md`, regenerated by `npm run docs`.
   Prose docs point at it; they do not repeat its counts. A hand-copied
   number is a future staleness bug.
2. **A change to any energy term, parameter, or typing rule ships together
   with a regenerated report.** `npm run docs:check` fails when the
   committed report differs from a fresh run.
3. **Every quantitative claim in prose must be re-verified before it is
   repeated** — counts, timings, residuals drift as the code moves. Check
   the source (report, test output, benchmark data), then write.
4. **The Halgren papers are the sole specification.** Third-party
   implementations (OpenBabel, RDKit, Tinker) may be studied for
   difficulties and used for numerical cross-checks only. Their source
   files, line numbers, and internal logic must never appear in our code
   comments or docs — only their published parameter files and observable
   output (`obenergy`, `analyze`, RDKit APIs).

## Verification etiquette

- Verify only when explicitly asked; one pass, then stop. Do not cascade.
- Full-suite runs (`npm test`) are for completion points, not mid-flight
  checks — scope verification to the file under change.
- Tests that compare floating-point trajectories across platforms need
  tolerance bands (last-ULP drift flips strict `<` at thresholds); see
  `tests/optimization.test.ts` for the pattern.

## Repo facts

- TypeScript (strict) → ESM in `dist/`. Zero runtime dependencies.
  Build: `npm run build` (tsc). Test: `npm test` (vitest).
- Python appears only in build-time scripts (parameter extraction,
  reference generation); the library itself never needs it.
- CI runs typecheck + build + tests on Node 20/22/24 (GitHub Actions,
  `.github/workflows/tests.yml`). Keep `package-lock.json` tracked.
- Validation inputs: Halgren's 761-molecule suite under
  `tests/fixtures/validation-suite/` (Nov 1998 revision), including the
  BatchMin log (`MMFF94_bmin.log`) — tracked, load-bearing, do not
  gitignore.
- Reference logs live in `tests/references/*.mmff94.log` (OpenBabel) and
  `tests/references/tinker/*.log` (Tinker). A fixture without a reference
  fails loudly unless listed in `INTENTIONALLY_UNREFERENCED` with a reason.
- Windows dev box: OpenBabel reference generation needs an explicit
  `BABEL_DATADIR` (see `tests/scripts/` recipes). Tinker lives on lenovo
  (`ssh lenovo`), reachable per the tinker-running skill.

## Where things are

- `src/types.ts` — the data model (`Molecule`, `TypedMolecule`: types +
  partial charges attached; optional `formal_charge` per atom).
- `src/mmff94/assign-atom-types.ts` — the typing decision tree (hardest
  piece; element, coordination, bond orders, neighbor types, rings,
  formal charge).
- `src/mmff94/{energy,gradient}/` — one readable function per term, plus
  `total.ts` sums. Ground truth for the fast path.
- `src/optimize/l-bfgs.ts`, `steepest-descent.ts`, `fast-system.ts` — the
  optimizers and the compiled kernel they run on.

  the variant/provenance certification. `docs/benchmark.md` — optimizer
  methodology. `docs/implementer-notes.md` — forensics index.

## MMFF94 peculiarities — get these wrong and it isn't MMFF94

The full derivations live beside the code that implements them; these are
the tripwires:

1. **Buffered 14-7 vdW**, not Lennard-Jones (`van-der-waals.ts`).
2. **Charges come from bond charge increments + eq. (15) formal-charge
   sharing** — q⁰ flows use the NEIGHBOR's α (fcadj), and type 32's q⁰ is
   environment-dependent (−½ carboxylate O; 0 on sulfone/nitro/nitrate O).
   Transcribing the sharing with the atom's own α breaks carboxylates.
3. **Stretch-bend is a class-II cross term** — omitted by simplified ports.
4. **Torsions are three-term Fourier series** (n = 1, 2, 3 with γ =
   0°/180°/0°) — single-cosine reductions are wrong.
5. **Parameters resolve by class, not priority.** Class selection is a
   chemical question answered in `parameter-classes.ts` (BTij flags →
   ATijk → TTijkl → STijk remap); the empirical rules generate what tables
   lack (`empirical.ts`). `lookup_param()` wildcards are class-0 fallbacks
   only.
6. **1–4 scaling: electrostatics ×0.75 only.** vdW is *not* scaled at 1–4
   (Halgren 1996 p. 496); ×0.5 is the MM2/GAFF convention.
7. **Out-of-plane bending, not improper torsion** — evaluated at every
   tri-coordinate center; k_oop's sign encodes chemistry (zero for amine N;
   negative for amide N gives deliberate pyramidalization — do not "fix"
   it; MMFF94s is the planarizing variant).
8. **Conversion factors**: 143.9325 (bond), 0.043844 (angle/oop), 2.51210
   (stretch-bend), 332.0716 (electrostatics, buffered r + 0.05). Note
   OpenBabel internally uses half-valued MM2-style units — cross-check
   against Halgren's tables or RDKit, not raw obenergy totals.
